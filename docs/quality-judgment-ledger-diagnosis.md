# 判断库架构诊断报告

**受检系统**：OpenDesign 内容质量系统

**诊断日期**：2026-08-13
**依据材料**：`0011_curation_decisions.sql`、Admin API repository/types、每日策展脚本与后台 domain/provider

## 结论

该系统已具备判断库基础，但仍有短板。五问中 1 条不合格、1 条部分合格；风险等级为中。

## 五问诊断结果

| # | 检查项 | 结果 | 证据 |
| --- | --- | --- | --- |
| 1 | 主语类型 | 合格 | `curation_decisions.discovery_id uuid` 外键指向 `discoveries(id)` |
| 2 | 能否回答“谁认为” | 部分合格 | AI 有 `model`，人工有 `reviewed_by text`，但缺统一 holder 类型与独立判断事件 |
| 3 | 旧结论处理方式 | 不合格 | 人工终审直接更新同一行的 `review_status/final_recommendation`，没有独立事件和 `supersedes` 链 |
| 4 | 不变量实现处数 | 合格 | 人工终审写入只经过数据库函数；应用和浏览器不能直写基础表 |
| 5 | 展示记录 | 不合格但延期 | 当前没有策展 impression 事件，无法计算“推了 N 条、处理了 M 条” |

## 已命中或将命中的故障

### FC-04 · 判断成立时间与演变不足

**当前状态**：结构上已发生。AI 的 `decided_at` 和人工 `reviewed_at` 存在，但人工终审不是独立判断；查询“管理员当时作出的完整判断及其取代对象”需要拼接可变行状态，无法直接得到事件链。

**根治方向**：新增 append-only 人工终审事件，单列 `as_of/recorded_at`，用 `supersedes_decision_id` 指向 AI 判断；原 AI 行不覆盖。

### FC-05 · 没有展示记录

**当前状态**：尚未形成排序学习能力。系统记录终审动作，但不知道哪些 AI 判断曾被展示后默默跳过。

**根治方向**：下一阶段增加 impression/feedback 事件，并只把反馈接到待审队列排序，不修改 AI 或人工判断的可信度。

## 不改造的后果

- **现在**：后台能显示最终状态，但 Agent 无法稳定读取完整的人工判断事件和取代链。
- **三个月后**：策略版本与复核记录增多后，难以复盘某次人工结论当时依据什么、取代了哪条判断。
- **接入 Agent 后**：若 Agent 直接依赖可变终态，会把“当前结果”误当成“唯一历史判断”。

## 增量迁移计划

1. 新增 `curation_review_events`，保留现有 `curation_decisions`，不重写。
2. 让唯一终审函数在同一事务中追加事件并设置当前索引字段。
3. 只读视图同时暴露 AI 判断与人工事件的五位结构。
4. UI 切到新字段；旧终态字段保留一个版本周期兼容。
5. 后续再加 impression/feedback，反馈只影响排序。

真正的硬工程是新事件表、权限边界和兼容迁移；无需重写现有策展器。

## 本次诊断的边界

- 本诊断只检查判断结构，不评价模型内容质量或检索算法。
- 未读取生产数据、未执行生产迁移。
- impression 延期到下一 spec，不在本次实现范围。
